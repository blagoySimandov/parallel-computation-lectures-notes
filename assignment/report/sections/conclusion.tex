\section{Conclusion}

All-to-All Bucket Sort gave the best result, with a speedup of 6.35 at NP = 8.
Bucket Sort was second with 5.41, Shell Sort was third with 5.16, and Odd-Even Sort was fourth with 4.58.
Direct Sort gave the lowest speedup, 2.80, because the root merges all the chunks in series.

The results show that the best algorithms divide the computation equally and keep the serial part small.
All-to-All Bucket Sort does this, because each process sorts only its own bucket and the root does not merge.
Odd-Even Sort divides the computation equally, but each exchange phase merges two blocks.
The merge work per process does not shrink as NP grows, and the communication time goes up.
Shell Sort uses the same exchange, but its first phase moves the data far, thus it is faster than Odd-Even Sort.


This experiment had two limits.
All the processes ran on one machine, thus the communication time was shorter than on a real cluster.

Due to the way the data was generated, the input data had a uniform distribution. For the two bucket sorting algorithms this meant that
all buckets had around the same amount of data. 
With data that does not have a uniform distribution, the two bucket algorithms can become slower.
